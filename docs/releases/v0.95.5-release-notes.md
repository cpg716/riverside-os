# Riverside OS v0.95.5 Release Notes

- Status: **Release candidate. GitHub Actions and published asset verification must pass for the exact `v0.95.5` tag before installation.**
- Target version: **v0.95.5**
- Prepared: **2026-07-26**

## Register workflow and presentation

- Product search now distinguishes active searching, no matches, unavailable
  Main Hub results, and exact scanned-SKU failures without clearing a valid
  prior selection.
- Parent products use one grouped variation surface with large sequential
  choices, preserved selections, and complete price-range loading before an
  item can be added.
- The action carousel, keypad, salesperson selector, payment workspace,
  shipping shortcut, and service-line presentation remain usable at Register
  and tablet dimensions without hidden or partially actionable controls.
- Repeated low-value Register errors are deduplicated so staff see the
  operational problem without a toast storm obscuring the sale.

## Returns, exchanges, and customer search

- Staged returns remain visible as the actual merchandise line with SKU,
  variation, negative value, and source Transaction Record.
- A reviewed return-value correction is retained on the specific returned line,
  cannot exceed the original paid value, and drives the same exchange or refund
  settlement amount while preserving original tax components.
- Customer lookup cancels stale requests and keeps exact customer selection
  stable across ambiguous scans and overlapping searches.
- Meilisearch is used only when its indexed document is at least as current as
  PostgreSQL authority; stale or unavailable search evidence falls back
  explicitly instead of being treated as current.

## Alterations intake and custody

- Register now separates **Quick Add**, which creates a tracked garment record,
  from **Fee Only**, which adds a non-taxable service charge without custody,
  due-date, pickup, or tailor-queue work.
- Full intake keeps garment choice, fitting decision, work requested, timing,
  capacity, fee, tag, and notes in one wide workspace with a pinned save action.
- Alteration services remain linked to the source merchandise or
  customer-owned garment and retain intake, status, work-item, and pickup audit
  history.
- Universal search can open the exact alteration directly into its planning and
  reassignment workspace.

## RMS Charge, Helcim, and reporting

- Register customer results show current RMS Charge eligibility evidence, while
  actual balance and approval remain part of the RMS Charge workflow.
- Standard and 90 Day RMS plans use explicit approval numbers. A weekly account
  record with no open-to-buy requires audited Manager Access before the sale can
  be recorded.
- A simple take-now sale approved by Helcim can be recorded locally after Main
  Hub confirmation is lost, prints a pending-sync receipt, and replays the exact
  checkout idempotently after reconnection. Fulfillment-dependent workflows
  remain live-recovery only.
- RMS program tenders stay distinct from ordinary card activity in Register and
  Daily Sales reporting, while non-merchandise service activity is reported
  outside merchandise sales without changing tender truth.
- Payments Operations marks stale synchronization clearly so an older completed
  import cannot be mistaken for current processor evidence.

## Documentation and release boundary

- Staff Help manuals were refreshed for Register, alterations, returns,
  payments, RMS Charge, search, and related settings surfaces. Generated Help
  metadata is part of the release gate.
- The retained July 21 Counterpoint false-fulfillment incident remains
  unresolved: 557 traceability reviews, one current exception, nine failed
  recognition recoveries, and zero verified records. Publishing v0.95.5 does
  not resolve that cohort or authorize additional record-status changes.
- Source, tag, GitHub Actions, published assets, installation, Main Hub
  readiness, and physical store certification remain separate evidence. See
  [`v0.95.5-certification.md`](v0.95.5-certification.md).
